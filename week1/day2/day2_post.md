# [LeetCode 75 Day 2] 배열 순회와 그리디로 조건 판단하기

LeetCode 75 두 번째 날에는 배열을 순회하면서 조건에 맞는 결과를 만드는 문제 두 개를 풀었다. 첫 번째 문제는 배열의 최댓값을 기준으로 각 원소를 비교하는 문제였고, 두 번째 문제는 현재 위치와 인접한 위치의 상태를 함께 확인해야 하는 그리디 문제였다.

문제 자체는 어렵지 않아 보였지만, 실제로 코드를 작성하면서 타입 힌트와 배열 초기화, 순회 범위, 비교 연산자와 대입 연산자의 차이처럼 기본적인 부분에서 여러 번 막혔다. 이번 글에서는 처음 세운 접근과 구현 과정에서 수정한 내용을 함께 정리한다.

## 1. Kids With the Greatest Number of Candies - 가장 많은 사탕을 가질 수 있는 아이

각 아이가 가진 사탕의 개수가 `candies` 배열로 주어진다. 한 아이에게 여분의 사탕을 모두 주었을 때, 그 아이가 가장 많은 사탕을 가진 아이가 될 수 있는지 판단하는 문제다.

가장 많은 사탕을 가진 아이가 여러 명이어도 되기 때문에, 기존 최댓값보다 크기만 한 것이 아니라 같아도 `True`가 된다.

```python
class Solution:
    def kidsWithCandies(
        self, candies: list[int], extraCandies: int
    ) -> list[bool]:
        max_num = 0
        result = [False] * len(candies)

        for candy in candies:
            if max_num < candy:
                max_num = candy

        for i in range(len(candies)):
            if candies[i] + extraCandies >= max_num:
                result[i] = True

        return result
```

처음에는 다음과 같은 순서로 접근했다.

1. `candies`를 순회하면서 현재 가장 큰 사탕 개수를 찾는다.
2. 결과를 저장할 리스트를 아이들의 수만큼 만든다.
3. 각 아이의 사탕에 `extraCandies`를 더한다.
4. 그 값이 기존 최댓값 이상이라면 `True`, 아니라면 `False`를 저장한다.

예를 들어 다음과 같은 입력이 주어진다고 하자.

```python
candies = [2, 3, 5, 1, 3]
extraCandies = 3
```

현재 가장 많은 사탕은 `5`개다. 각 아이에게 사탕 3개를 추가했을 때의 결과는 다음과 같다.

```text
2 + 3 = 5  → True
3 + 3 = 6  → True
5 + 3 = 8  → True
1 + 3 = 4  → False
3 + 3 = 6  → True
```

따라서 최종 결과는 다음과 같다.

```python
[True, True, True, False, True]
```

풀면서 걸렸던 부분은 결과 리스트를 어떻게 만들어야 하는지였다. 아이마다 하나의 불리언 값을 저장해야 하므로, `candies`와 같은 길이의 리스트가 필요했다.

```python
result = [False] * len(candies)
```

이렇게 작성하면 `candies`의 길이만큼 `False`가 들어 있는 리스트를 만들 수 있다. 이후 조건을 만족하는 위치만 `True`로 바꾸면 된다.

또 하나 확인한 점은 비교 조건이다.

```python
candies[i] + extraCandies >= max_num
```

여기서는 `>`가 아니라 `>=`를 사용해야 한다. 다른 아이와 같은 개수의 사탕을 가지더라도 공동으로 가장 많은 사탕을 가진 아이가 될 수 있기 때문이다.

최댓값을 찾는 순회와 결과를 만드는 순회를 각각 한 번씩 수행하므로 시간 복잡도는 `O(n)`이다. 반환할 결과 리스트가 필요하므로 공간 복잡도는 `O(n)`이다.

## 2. Can Place Flowers - 인접하지 않게 꽃 심기

두 번째 문제에서는 `0`과 `1`로 이루어진 `flowerbed` 배열이 주어진다. `0`은 빈 화단이고 `1`은 이미 꽃이 심어진 화단이다.

새로운 꽃은 다른 꽃과 인접하게 심을 수 없다. 따라서 현재 칸에 꽃을 심으려면 현재 칸과 왼쪽 칸, 오른쪽 칸이 모두 비어 있어야 한다. 왼쪽부터 가능한 자리에 바로 꽃을 심는 그리디 방식으로 해결했다.

```python
class Solution:
    def canPlaceFlowers(self, flowerbed: list[int], n: int) -> bool:
        planted = 0
        flowerbed = [0] + flowerbed + [0]

        for i in range(1, len(flowerbed) - 1):
            if (
                flowerbed[i] == 0
                and flowerbed[i - 1] == 0
                and flowerbed[i + 1] == 0
            ):
                flowerbed[i] = 1
                planted += 1

                if planted >= n:
                    return True

        return planted >= n
```

핵심은 꽃을 심은 뒤 배열의 값을 실제로 `1`로 변경하는 것이다.

```python
flowerbed[i] = 1
```

이렇게 해야 다음 위치를 검사할 때 방금 심은 꽃도 인접한 꽃으로 처리된다. 왼쪽부터 꽃을 심을 수 있는 가장 빠른 위치에 심으면 이후에 사용할 수 있는 공간을 불필요하게 줄이지 않으므로 그리디 방식이 성립한다.

처음 구현에서는 배열의 가운데 부분만 순회하려고 했다.

```python
for i in range(1, len(flowerbed) - 1):
```

하지만 이렇게만 작성하면 첫 번째 칸과 마지막 칸을 검사하기가 불편하다. 양 끝에는 한쪽 이웃이 존재하지 않기 때문이다. 이를 단순하게 처리하기 위해 배열의 양옆에 가상의 빈 화단을 추가했다.

```python
flowerbed = [0] + flowerbed + [0]
```

예를 들어 `[1, 0, 0, 0, 1]`은 코드 내부에서 다음과 같이 바뀐다.

```python
[0, 1, 0, 0, 0, 1, 0]
```

이제 원래 배열의 첫 번째 칸과 마지막 칸도 다른 칸과 같은 조건으로 검사할 수 있다.

구현하면서 수정해야 했던 부분은 여러 가지였다. 먼저 반복문의 기준을 `n`으로 잡으면 안 된다.

```python
for i in range(1, n - 1):
```

`n`은 심어야 하는 꽃의 개수이지 화단의 길이가 아니다. 화단 전체를 검사하려면 `len(flowerbed)`를 기준으로 순회해야 한다.

또한 처음에는 양옆만 확인했는데, 현재 칸 자체가 비어 있는지도 반드시 확인해야 한다.

```python
flowerbed[i] == 0
```

현재 칸에 이미 꽃이 있다면 양옆이 비어 있더라도 새로운 꽃을 심을 수 없기 때문이다.

비교 연산자와 대입 연산자의 차이도 다시 확인했다.

```python
flowerbed[i] == 1  # 1과 같은지 비교
flowerbed[i] = 1   # 값을 1로 변경
```

꽃을 심었다는 상태를 배열에 반영하려면 `==`가 아니라 `=`를 사용해야 한다.

화단을 한 번 순회하므로 시간 복잡도는 `O(n)`이다. 현재 코드는 양옆에 `0`을 추가한 새로운 리스트를 만들기 때문에 공간 복잡도도 `O(n)`이다.

## 3. 스스로 묻고 답한 질문들

### Q. `List[int]`를 사용했는데 왜 `List is not defined` 오류가 발생했을까?

`List`는 파이썬의 기본 이름이 아니라 `typing` 모듈에 들어 있는 타입이기 때문이다. 따라서 대문자 `List`를 사용하려면 다음과 같이 가져와야 한다.

```python
from typing import List
```

현재 사용 중인 Python 3.13에서는 기본 타입인 소문자 `list`를 그대로 사용할 수도 있다.

```python
def kidsWithCandies(
    self, candies: list[int], extraCandies: int
) -> list[bool]:
```

이번 코드에서는 별도의 import가 필요 없는 `list[int]` 방식을 사용했다.

### Q. 결과 리스트를 처음부터 모두 `True`로 만들어도 될까?

가능하다.

```python
result = [True] * len(candies)
```

이후 모든 위치에 비교 결과를 다시 저장한다면 초기값이 `True`인지 `False`인지는 최종 결과에 영향을 주지 않는다.

```python
result[i] = candies[i] + extraCandies >= max_num
```

다만 조건을 만족하는 위치만 바꾸는 방식이라면 기본값을 `False`로 만드는 편이 더 자연스럽다.

### Q. `True if 조건 else False`를 꼭 사용해야 할까?

사용하지 않아도 된다. 비교식 자체의 결과가 이미 `True` 또는 `False`이기 때문이다.

```python
result[i] = candies[i] + extraCandies >= max_num
```

### Q. Can Place Flowers에서 왜 꽃을 심은 즉시 배열을 수정해야 할까?

꽃을 심은 결과가 다음 위치의 판단에 영향을 주기 때문이다. 예를 들어 `[0, 0, 0]`의 첫 번째 칸에 꽃을 심었다면 배열의 상태를 `[1, 0, 0]`으로 변경해야 한다. 그래야 두 번째 칸을 확인할 때 왼쪽에 꽃이 있다는 사실을 알 수 있다.

배열을 수정하지 않으면 서로 인접한 위치에 꽃을 여러 번 심었다고 잘못 계산할 수 있다.

### Q. 꽃을 심을 수 있는 개수가 정확히 `n`과 같아야 할까?

아니다. `n`개 이상 심을 수 있다면 그중 `n`개만 심으면 되므로 정답은 `True`다.

```python
planted >= n
```

따라서 `planted == n`이 아니라 `planted >= n`으로 비교하는 것이 의도를 더 정확하게 표현한다.

### Q. 양옆에 가상의 `0`을 추가하지 않고도 풀 수 있을까?

가능하다. 첫 번째와 마지막 위치를 별도의 경계 조건으로 처리하면 된다.

```python
left_empty = i == 0 or flowerbed[i - 1] == 0
right_empty = i == len(flowerbed) - 1 or flowerbed[i + 1] == 0
```

가상의 빈칸을 추가하는 방식은 코드가 단순해진다는 장점이 있고, 경계 조건을 직접 검사하는 방식은 새로운 리스트를 만들지 않아 추가 공간을 `O(1)`로 줄일 수 있다는 장점이 있다.

## 정리하며

Day 2에서는 배열을 순회하면서 기준값과 비교하는 방법, 같은 길이의 결과 리스트를 만드는 방법, 그리고 현재 상태를 수정하면서 다음 판단에 반영하는 그리디 방식을 연습했다.

특히 알고리즘의 큰 방향이 맞더라도 반복문의 범위나 현재 칸에 대한 조건 하나가 빠지면 전체 결과가 달라질 수 있다는 점을 확인했다. `List`와 `list`의 차이, `==`와 `=`의 차이처럼 기본적인 문법도 실제 오류를 통해 다시 정리할 수 있었다.

첫 번째 문제에서는 전체 배열의 최댓값을 기준으로 각 원소를 판단했고, 두 번째 문제에서는 현재 위치뿐 아니라 양옆의 상태까지 함께 살펴봤다. 다음 문제를 풀 때도 반복문이 무엇을 기준으로 돌아야 하는지, 조건문이 필요한 상태를 모두 확인하고 있는지를 먼저 점검해야겠다.
