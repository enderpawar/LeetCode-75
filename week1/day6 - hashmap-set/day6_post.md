# [LeetCode 75 Day 6] 딕셔너리와 집합으로 중복을 다루기

LeetCode 75 여섯 번째 날에는 배열에서 값의 등장 횟수를 세는 문제와, 두 배열에 공통으로 들어 있지 않은 값을 찾는 문제를 풀었다. 두 문제 모두 중복을 다뤄야 했고, 리스트만 사용했을 때보다 딕셔너리와 집합을 사용했을 때 코드와 시간 복잡도가 어떻게 달라지는지 확인할 수 있었다.

이번 문제들을 풀면서 딕셔너리는 `값 → 등장 횟수`처럼 서로 관련된 정보를 저장할 때, 집합은 중복 제거와 포함 여부 검사, 차집합을 구할 때 알맞다는 점을 정리했다.

## 1. Unique Number of Occurrences - 등장 횟수도 모두 다른지 확인하기

정수 배열 `arr`에 있는 각 값의 등장 횟수가 모두 서로 다르면 `True`, 같은 등장 횟수를 가진 값이 하나라도 있으면 `False`를 반환하는 문제다.

예를 들어 `[1, 2, 2, 1, 1, 3]`에서는 1이 3번, 2가 2번, 3이 1번 등장한다. 등장 횟수 `3, 2, 1`이 모두 다르므로 결과는 `True`다.

```python
from typing import List


class Solution:
    def uniqueOccurrences(self, arr: List[int]) -> bool:
        counts = {}

        for num in arr:
            counts[num] = counts.get(num, 0) + 1

        occurrences = list(counts.values())

        return len(occurrences) == len(set(occurrences))
```

처음에는 배열의 인덱스를 숫자 자체처럼 사용해 횟수를 기록하는 방법을 생각했다. 하지만 문제의 숫자 범위에는 음수도 있으므로 보정값이 필요하고, 실제로 등장하지 않는 숫자를 위한 공간까지 만들어야 한다. 값의 범위가 넓고 배열이 짧다면 사용하지 않는 공간이 많아진다.

그래서 딕셔너리 `counts`에 숫자를 키로, 등장 횟수를 값으로 저장했다. 다음 코드에서 `counts.get(num, 0)`은 `num`이 이미 키로 존재하면 현재 값을 가져오고, 없으면 기본값 `0`을 반환한다.

```python
counts[num] = counts.get(num, 0) + 1
```

중요한 점은 `get()` 자체가 딕셔너리의 값을 증가시키지는 않는다는 것이다. 오른쪽에서 기존 횟수에 1을 더한 다음, 그 결과를 왼쪽의 `counts[num]`에 다시 대입하기 때문에 횟수가 갱신된다.

모든 횟수를 센 뒤에는 `counts.values()`로 등장 횟수만 꺼낸다. 이를 집합으로 바꾸면 같은 횟수가 자동으로 하나로 합쳐진다. 따라서 집합으로 바꾸기 전후의 길이가 같으면 모든 횟수가 서로 다르고, 길이가 줄었다면 중복된 횟수가 있다는 뜻이다.

```text
arr = [1, 2, 2, 1, 1, 3]

counts = {1: 3, 2: 2, 3: 1}
occurrences = [3, 2, 1]
set(occurrences) = {1, 2, 3}

길이가 3으로 같음 → True
```

배열을 한 번 순회하고 등장한 값의 개수를 `k`라고 할 때 횟수 목록과 집합을 만드는 데 `O(k)`가 걸린다. `k`는 최대 배열 길이 `n`이므로 평균 시간 복잡도는 `O(n)`이다. 딕셔너리와 집합에 최대 `n`개의 값을 저장하므로 공간 복잡도도 `O(n)`이다.

## 2. Find the Difference of Two Arrays - 두 배열의 서로 다른 값 찾기

두 정수 배열 `nums1`, `nums2`가 주어졌을 때 다음 두 목록을 반환하는 문제다.

- `answer[0]`: `nums1`에는 있지만 `nums2`에는 없는 서로 다른 값
- `answer[1]`: `nums2`에는 있지만 `nums1`에는 없는 서로 다른 값

결과 안에서 값의 순서는 자유롭다.

처음에는 각 배열을 순회하면서 `not in`으로 상대 배열에 값이 없는지 확인했다. 같은 값을 결과에 여러 번 넣지 않도록 결과 리스트에도 다시 `not in` 검사를 했다.

```python
class Solution:
    def findDifference(self, nums1, nums2):
        answer = [[], []]

        for num in nums1:
            if num not in nums2 and num not in answer[0]:
                answer[0].append(num)

        for num in nums2:
            if num not in nums1 and num not in answer[1]:
                answer[1].append(num)

        return answer
```

이 풀이의 결과는 맞지만, 리스트의 `in`과 `not in`은 원하는 값을 찾을 때까지 원소를 앞에서부터 확인한다. 길이가 `m`인 `nums1`의 각 값마다 길이가 `n`인 `nums2`를 검사하는 데 `O(mn)`이 걸릴 수 있다. 결과 리스트에서 중복을 다시 검사하는 비용까지 포함하면 전체 최악의 시간 복잡도는 `O(mn + m² + n²)`, 간단히 나타내면 `O((m + n)²)`이다.

두 배열을 집합으로 바꾸면 중복이 먼저 제거되고, 문제에서 원하는 값은 그대로 두 집합의 차집합이 된다.

```python
from typing import List


class Solution:
    def findDifference(
        self, nums1: List[int], nums2: List[int]
    ) -> List[List[int]]:
        set1 = set(nums1)
        set2 = set(nums2)

        return [list(set1 - set2), list(set2 - set1)]
```

`set1 - set2`는 `set1`에만 있는 값을 구하고, `set2 - set1`은 `set2`에만 있는 값을 구한다. 집합은 이미 중복된 값을 하나만 보관하므로 결과의 중복을 따로 검사할 필요도 없다. 마지막에는 문제에서 리스트 형태를 요구하므로 각 차집합을 `list()`로 변환한다.

```text
nums1 = [1, 2, 3, 3]
nums2 = [1, 1, 2, 2]

set1 = {1, 2, 3}
set2 = {1, 2}

set1 - set2 = {3}
set2 - set1 = set()

결과 → [[3], []]
```

두 배열의 길이를 각각 `m`, `n`이라고 하면 집합을 만들고 차집합을 구하는 평균 시간 복잡도는 `O(m + n)`이다. 두 집합과 결과를 저장하는 데 필요한 공간 복잡도도 `O(m + n)`이다.

## 3. 스스로 묻고 답한 질문들

### Q. `dict.get(key, 0)`은 딕셔너리에 없는 키를 자동으로 추가할까?

아니다. `get()`은 키가 없을 때 지정한 기본값을 반환할 뿐, 딕셔너리 자체를 바꾸지는 않는다.

```python
counts = {}
counts.get(1, 0)
print(counts)  # {}
```

이번 코드에서는 반환된 값에 1을 더해 `counts[num]`에 대입했기 때문에 새 키가 추가되거나 기존 값이 갱신된다.

### Q. 등장 횟수 목록을 꼭 `list()`로 바꿔야 할까?

꼭 필요하지는 않다. `counts.values()`가 반환하는 딕셔너리 뷰도 `len()`을 사용할 수 있고 집합으로 변환할 수 있다.

```python
occurrences = counts.values()
return len(occurrences) == len(set(occurrences))
```

다만 리스트로 바꾸면 현재 등장 횟수들이 별도의 목록으로 저장된다는 점이 코드에서 더 분명하게 보인다.

### Q. 빈 리스트에 `answer[0][0] = num`처럼 바로 대입하면 왜 오류가 날까?

빈 리스트에는 아직 0번 인덱스가 존재하지 않기 때문이다. 인덱스 대입은 이미 존재하는 위치의 값을 바꿀 때 사용한다. 리스트 끝에 새 값을 추가하려면 `append()`를 사용해야 한다.

```python
values = []
values[0] = 3  # IndexError
values.append(3)  # [3]
```

### Q. 집합을 리스트로 바꾸면 결과 순서가 달라져도 괜찮을까?

이 문제는 결과 안의 정수 순서를 자유롭게 반환해도 된다고 명시한다. 집합은 순서를 기준으로 사용하는 자료구조가 아니므로 `list(set1 - set2)`의 순서에 의존하면 안 되지만, 이 문제의 정답 조건에는 영향을 주지 않는다.

### Q. 집합의 포함 검사는 왜 리스트보다 빠를까?

리스트는 값을 앞에서부터 하나씩 비교하지만, 집합은 값의 해시를 이용해 저장 위치를 찾는다. 그래서 집합의 포함 여부 검사는 평균 `O(1)`이고, 리스트는 최악의 경우 리스트 전체를 확인해 `O(n)`이 걸린다. 이번 차집합 풀이가 이 차이를 이용한다.

## 정리하며

Day 6의 두 문제는 모두 중복을 다뤘지만 필요한 정보에 따라 자료구조가 달랐다. 값마다 횟수를 연결해야 하는 첫 번째 문제에는 딕셔너리를 사용했고, 중복을 없앤 값들의 포함 관계를 비교하는 두 번째 문제에는 집합을 사용했다.

특히 `dict.get()`은 값을 직접 바꾸는 함수가 아니라 기본값과 함께 값을 조회하는 함수라는 점을 분명히 했다. 또 리스트의 `not in`만으로도 정답을 만들 수 있지만, 문제의 조건을 집합의 차집합으로 옮기면 코드가 짧아질 뿐 아니라 평균 시간 복잡도도 `O(mn)`에서 `O(m + n)`으로 줄어든다는 점을 확인했다.
