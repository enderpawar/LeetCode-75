# [LeetCode 75 Day 4] 인덱스 하나로 "지금까지 처리한 위치"를 기억하기

LeetCode 75 네 번째 날에는 배열에서 0을 모두 뒤로 밀어내는 문제와, 한 문자열이 다른 문자열의 부분 수열인지 확인하는 문제를 풀었다. 두 문제 모두 배열이나 문자열을 한 번만 앞에서 뒤로 순회하고, 인덱스 변수 하나에 "지금까지 처리한 결과가 놓일 위치"를 담아 두는 방식으로 풀렸다.

Day 3에서 문자열을 나누고 합치는 문법을 정리했다면, 이번에는 값을 옮겨 담을 위치를 따로 관리하는 감각이 필요했다. 특히 첫 번째 문제는 배열의 사본을 만들지 않고 원본을 직접 수정해야 하는 조건이 있어서, 파이썬에서 in-place 수정이 정확히 무엇을 의미하는지도 함께 확인하게 됐다.

## 1. Move Zeroes - 0을 뒤로 밀어내기

정수 배열 `nums`에서 0이 아닌 값들의 상대적인 순서를 그대로 유지하면서, 모든 0을 배열의 끝으로 옮기는 문제다. 새 배열을 만들어 반환하는 것이 아니라 주어진 배열을 직접 수정해야 한다.

```python
class Solution:
    def moveZeroes(self, nums: List[int]) -> None:
        cnt = 0

        for i in range(len(nums)):
            if nums[i] != 0:
                nums[cnt] = nums[i]
                if cnt != i:
                    nums[i] = 0
                cnt += 1
```

처음 세운 방식은 0을 만날 때마다 그 뒤의 값들을 한 칸씩 앞으로 당겨오는 것이었다. 하지만 0 하나를 처리할 때마다 뒤쪽 전체를 옮겨야 하므로, 0이 많은 배열에서는 시간 복잡도가 `O(n^2)`이 된다.

그다음으로 떠올린 방식은 0의 개수를 세어 제거한 뒤 다시 정렬하고, 센 개수만큼 0을 뒤에 붙이는 것이었다. 이 방식은 정렬이 0이 아닌 값들의 순서를 바꿔 버리기 때문에 문제의 조건과 맞지 않는다. `[3, 0, 1]`은 `[3, 1, 0]`이 되어야 하는데, 정렬하면 `[1, 3, 0]`이 된다.

결국 사용한 방식은 `cnt`를 "0이 아닌 값을 다음에 써야 할 위치"로 쓰는 것이다. 배열을 순회하면서 0이 아닌 값을 만나면 그 값을 `cnt` 위치에 쓰고, 원래 자리는 0으로 바꾼 다음 `cnt`를 한 칸 오른쪽으로 옮긴다.

`[0, 1, 0, 3, 12]`를 넣으면 다음 순서로 진행된다.

```text
i=0, nums[0]=0   → 건너뜀                      [0, 1, 0, 3, 12], cnt=0
i=1, nums[1]=1   → nums[0]=1, nums[1]=0        [1, 0, 0, 3, 12], cnt=1
i=2, nums[2]=0   → 건너뜀                      [1, 0, 0, 3, 12], cnt=1
i=3, nums[3]=3   → nums[1]=3, nums[3]=0        [1, 3, 0, 0, 12], cnt=2
i=4, nums[4]=12  → nums[2]=12, nums[4]=0       [1, 3, 12, 0, 0], cnt=3
```

`cnt`가 항상 `i`보다 작거나 같기 때문에, 아직 확인하지 않은 값을 덮어쓰는 일은 생기지 않는다. `i` 앞쪽은 이미 확인이 끝난 구간이고, `cnt`부터 `i`까지는 0으로 채워진 구간이 된다.

여기서 `if cnt != i` 조건이 필요했다. `cnt`와 `i`가 같은 상황은 아직 0을 한 번도 만나지 않은 경우인데, 이때 `nums[cnt] = nums[i]`는 자기 자리에 자기 값을 넣는 것이라 아무 변화가 없다. 그 상태에서 `nums[i] = 0`을 실행하면 방금 남겨둔 값을 0으로 지워 버린다. `[1, 2]`처럼 0이 없는 배열이 `[0, 0]`이 되는 셈이다.

배열을 한 번만 순회하므로 시간 복잡도는 `O(n)`이다. 추가 배열 없이 `cnt` 하나만 사용하므로 공간 복잡도는 `O(1)`이다.

## 2. Is Subsequence - 부분 수열인지 확인하기

문자열 `s`가 문자열 `t`의 부분 수열인지 확인하는 문제다. 부분 수열은 `t`에서 일부 문자를 지워서 만들 수 있는 문자열이며, 남은 문자들의 순서는 원래 순서를 유지해야 한다. 예를 들어 `abc`는 `ahbgdc`의 부분 수열이다.

```python
class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        i = 0
        j = 0

        while i < len(s) and j < len(t):
            if s[i] == t[j]:
                i += 1
            j += 1

        return i == len(s)
```

포인터 두 개를 각각 `s`와 `t`의 앞에서 시작한다. `j`는 `t`를 한 칸씩 훑으면서 매번 증가하고, `i`는 `s[i]`와 같은 문자를 `t`에서 찾았을 때만 증가한다. 즉 `i`는 "`s`에서 지금까지 몇 글자를 맞췄는지"를 기억하는 값이다.

`s = "abc"`, `t = "ahbgdc"`의 진행 과정은 다음과 같다.

```text
j=0, t[0]='a' == s[0]='a'  → i=1
j=1, t[1]='h' != s[1]='b'
j=2, t[2]='b' == s[1]='b'  → i=2
j=3, t[3]='g' != s[2]='c'
j=4, t[4]='d' != s[2]='c'
j=5, t[5]='c' == s[2]='c'  → i=3
```

반복이 끝난 뒤 `i`가 `len(s)`와 같으면 `s`의 모든 문자를 순서대로 찾았다는 뜻이므로 `True`다. `t`를 끝까지 봤는데도 `i`가 `len(s)`에 도달하지 못했다면 `False`다.

찾은 문자를 그 자리에서 바로 쓰고 넘어가도 되는지 잠깐 고민했다. `s[i]`와 같은 문자가 `t`에 여러 번 나올 때, 가장 앞에 있는 것을 쓰는 선택이 손해가 되지 않는지가 문제였다. 앞쪽 문자를 쓰면 남은 `t`의 범위가 더 넓어지므로, 뒤쪽 문자를 골라서 성공하는 경우는 앞쪽 문자를 골라도 반드시 성공한다. 그래서 만나는 즉시 넘어가도 된다.

빈 문자열도 별도 처리 없이 통과한다. `s`가 `""`이면 `i < len(s)` 조건이 처음부터 거짓이라 반복문에 들어가지 않고, `i == len(s)`가 `0 == 0`이므로 `True`가 된다. 빈 문자열은 모든 문자열의 부분 수열이라는 정의와 일치한다.

각 포인터가 뒤로만 이동하므로 시간 복잡도는 `O(len(s) + len(t))`이다. 포인터 두 개만 사용하므로 공간 복잡도는 `O(1)`이다.

## 3. 스스로 묻고 답한 질문들

### Q. `moveZeroes`는 왜 아무것도 반환하지 않을까?

문제에서 배열의 사본을 만들지 말고 원본을 직접 수정하라고 요구했기 때문이다. 반환 타입도 `None`으로 지정되어 있고, 채점은 함수가 끝난 뒤 `nums`의 상태를 확인한다.

### Q. 그럼 `nums = [1, 3, 12, 0, 0]`처럼 새 리스트를 대입하면 안 될까?

안 된다. 이 코드는 함수 안의 `nums`라는 이름이 새 리스트를 가리키게 만들 뿐이고, 호출한 쪽이 들고 있는 원래 리스트는 그대로 남는다.

```python
nums = [1, 3, 12, 0, 0]   # 이름만 새 리스트를 가리킴
nums[:] = [1, 3, 12, 0, 0] # 원래 리스트의 내용을 교체
```

같은 리스트의 내용을 바꾸려면 인덱스에 값을 넣거나 `nums[:]`처럼 슬라이스에 대입해야 한다. Day 3에서 파이썬 문자열은 내용을 바꿀 수 없어 `list(s)`로 변환했는데, 리스트는 반대로 이렇게 제자리 수정이 가능하다.

### Q. `List[int]`는 왜 로컬에서 실행하면 에러가 날까?

LeetCode 편집기에는 `from typing import List`가 미리 들어가 있지만, 내 컴퓨터에서 파일을 그냥 실행하면 `List`라는 이름이 정의되어 있지 않아 `NameError`가 발생한다. 직접 실행할 때는 임포트를 추가하면 된다.

```python
from typing import List
```

파이썬 3.9부터는 내장 타입을 그대로 쓸 수 있어서 `list[int]`로 적어도 된다.

### Q. `Solution.isSubsequence(Solution, s, t)`처럼 호출해도 되는 걸까?

동작은 한다. 클래스에서 함수를 직접 꺼내 쓰면서 첫 번째 인자인 `self` 자리에 클래스 자체를 넘긴 형태다. 이 풀이는 `self`를 사용하지 않으므로 결과에 문제가 없지만, 원래 의도된 호출 방식은 인스턴스를 만들어 부르는 것이다.

```python
print(Solution().isSubsequence(s, t))
```

이렇게 쓰면 `self` 자리에 인스턴스가 자동으로 들어가므로 인자를 하나 덜 적는다.

### Q. `result` 변수를 두지 않고 바로 반환해도 될까?

된다. 처음에는 `result = False`로 두고 조건이 맞을 때 `True`로 바꿨는데, `i == len(s)`가 이미 참과 거짓 중 하나이므로 그 결과를 그대로 반환하면 된다.

```python
if i == len(s):
    result = True
return result

# 위 세 줄과 같은 뜻
return i == len(s)
```

### Q. `s`가 여러 개 주어진다면 같은 방식으로 괜찮을까?

문제의 후속 질문이 이 상황을 다룬다. `s`가 10억 개쯤 주어지고 `t`는 고정이라면, 매번 `t`를 처음부터 훑는 방식은 `t`의 길이만큼을 반복해서 다시 읽는다.

이때는 `t`를 미리 한 번만 훑어 문자별로 등장 인덱스 목록을 만들어 두고, `s`의 각 문자마다 "현재 위치보다 큰 첫 인덱스"를 이진 탐색으로 찾는 방식으로 바꿀 수 있다. 이번에는 `s`가 하나뿐이라 투 포인터 풀이를 그대로 두었다.

## 정리하며

Day 4에서는 두 문제 모두 인덱스 변수 하나에 진행 상황을 담아 해결했다. Move Zeroes의 `cnt`는 다음에 값을 써야 할 위치였고, Is Subsequence의 `i`는 지금까지 맞춘 글자 수였다. 이름과 의미는 다르지만, 앞에서 뒤로 한 번만 지나가면서 필요한 정보를 인덱스로 유지한다는 점은 같았다.

처음 떠올린 방식들이 왜 안 되는지 확인한 과정도 남길 만했다. 뒤쪽 값을 당겨오는 방식은 `O(n^2)`이 되고, 정렬하는 방식은 순서를 유지하라는 조건 자체를 어긴다. 조건을 다시 읽고 나서야 값을 옮겨 담을 위치를 따로 관리하는 방향으로 정리됐다.

파이썬 문법에서는 이름을 다시 대입하는 것과 객체의 내용을 바꾸는 것이 다르다는 점을 in-place 조건을 통해 확인했다. Day 3에서 문자열이 불변이라 리스트로 바꿔야 했던 것과 이어지는 내용이라, 두 문제를 같이 놓고 보니 구분이 분명해졌다.
