# [LeetCode 75 Day 3] 문자열을 나누고 다시 합치는 방법

LeetCode 75 세 번째 날에는 문자열의 단어 순서를 뒤집는 문제와 모음의 순서만 뒤집는 문제를 풀었다. 두 문제 모두 문자열의 일부를 원하는 순서로 바꾼 뒤 다시 문자열로 반환한다는 공통점이 있었다.

이번에는 알고리즘 자체뿐 아니라 파이썬 문자열을 다루는 방법을 함께 정리하게 됐다. `split()`으로 문자열을 단어 단위로 나누는 방법, 문자열이 직접 수정되지 않는 이유, 리스트를 다시 문자열로 만드는 `join()`의 역할을 코드 안에서 확인했다.

## 1. Reverse Words in a String - 단어 순서 뒤집기

문자열 `s`에 포함된 단어의 순서를 반대로 바꾸는 문제다. 단어 사이에 공백이 여러 개 있거나 문자열의 앞뒤에 공백이 있어도, 반환할 문자열에서는 단어 사이에 공백이 하나만 남아야 한다.

```python
class Solution:
    def reverseWords(self, s: str) -> str:
        words = s.split()
        res = " ".join(words[::-1])

        return res
```

처음에는 문자열을 한 문자씩 확인해야 하는지 생각했지만, 이 문제에서는 단어 단위로 나누는 것이 더 간단했다.

```python
words = s.split()
```

구분자를 지정하지 않은 `split()`은 연속된 공백을 하나의 구분 영역으로 처리하고, 문자열 양끝의 공백도 제거한다.

```python
s = "  hello   world  "
words = s.split()

# ["hello", "world"]
```

그다음 슬라이싱으로 단어의 순서를 뒤집었다.

```python
words[::-1]
```

마지막으로 단어 사이에 공백 하나를 넣어 다시 문자열로 합쳤다.

```python
" ".join(words[::-1])
```

예를 들어 다음 문자열은:

```text
"  the sky   is blue  "
```

아래 과정을 거친다.

```python
["the", "sky", "is", "blue"]
["blue", "is", "sky", "the"]
"blue is sky the"
```

입력 문자열을 나누고 결과 문자열을 만드는 과정에서 전체 문자를 확인하므로 시간 복잡도는 `O(n)`이다. 단어 리스트와 결과 문자열을 만들기 때문에 공간 복잡도는 `O(n)`이다.

## 2. Reverse Vowels of a String - 모음 위치만 뒤집기

문자열에 들어 있는 모음의 위치만 서로 뒤집는 문제다. 모음은 `a`, `e`, `i`, `o`, `u`이며 대문자도 함께 처리해야 한다.

처음 세운 방식은 문자열을 순회하면서 모음의 위치를 `loc`에 기록한 다음, `loc`의 양끝에 저장된 위치를 차례대로 교환하는 것이었다.

```python
class Solution:
    def reverseVowels(self, s: str) -> str:
        str2 = "aeiouAEIOU"
        loc = []

        res = list(s)

        for i in range(len(s)):
            if s[i] in str2:
                loc.append(i)

        for j in range(len(loc) // 2):
            res[loc[j]], res[loc[-j - 1]] = (
                res[loc[-j - 1]],
                res[loc[j]],
            )

        return "".join(res)
```

예를 들어 `leetcode`에서 모음이 있는 인덱스는 다음과 같다.

```python
loc = [1, 2, 5, 7]
```

첫 번째 반복에서는 `loc[0]`과 `loc[-1]`, 즉 인덱스 `1`과 `7`의 문자를 교환한다. 두 번째 반복에서는 `loc[1]`과 `loc[-2]`, 즉 인덱스 `2`와 `5`의 문자를 교환한다.

```text
leetcode → leotcede
```

여기서 `-loc[j] - 1`과 `loc[-j - 1]`은 의미가 다르다는 점이 중요했다.

```python
res[-loc[j] - 1]  # 문자열 전체에서 대칭인 위치
res[loc[-j - 1]]  # 뒤에서 j번째 모음의 실제 위치
```

이 문제에서는 두 번째 표현을 사용해야 한다. 뒤집어야 하는 대상은 문자열 전체가 아니라 `loc`에 기록된 모음들이기 때문이다.

구현 과정에서는 먼저 `str`과 `s`를 혼동했다.

```python
len(str)
```

여기서 `str`은 입력 문자열이 아니라 파이썬의 문자열 타입 자체다. 따라서 길이를 구할 수 없고 `TypeError`가 발생한다. 함수가 전달받은 문자열의 길이는 `len(s)`로 구해야 한다.

또한 다음처럼 문자열을 그대로 `res`에 넣은 뒤 문자를 교환할 수는 없다.

```python
res = s
res[0] = "a"
```

파이썬 문자열은 생성된 뒤 내부 문자를 직접 바꿀 수 없는 불변 객체다. 따라서 먼저 수정 가능한 리스트로 변환해야 한다.

```python
res = list(s)
```

모든 교환이 끝난 뒤에는 문자 리스트를 다시 문자열로 합쳐 반환한다.

```python
return "".join(res)
```

문자열을 한 번 순회하고 모음 위치의 절반만큼 교환하므로 시간 복잡도는 `O(n)`이다. 문자 리스트와 모음 위치 리스트를 만들기 때문에 공간 복잡도는 `O(n)`이다.

## 3. 모음 위치를 저장하지 않는 투 포인터 풀이

직접 작성한 풀이는 정상적으로 동작하지만, 모든 모음의 위치를 먼저 저장하지 않고도 풀 수 있다. 왼쪽과 오른쪽에 포인터를 하나씩 놓고, 양쪽에서 가장 가까운 모음을 찾을 때마다 바로 교환하는 방식이다.

```python
class Solution:
    def reverseVowels(self, s: str) -> str:
        vowels = "aeiouAEIOU"
        res = list(s)

        left = 0
        right = len(res) - 1

        while left < right:
            while left < right and res[left] not in vowels:
                left += 1

            while left < right and res[right] not in vowels:
                right -= 1

            res[left], res[right] = res[right], res[left]

            left += 1
            right -= 1

        return "".join(res)
```

실행 순서는 다음과 같다.

1. `left`를 오른쪽으로 이동하며 모음을 찾는다.
2. `right`를 왼쪽으로 이동하며 모음을 찾는다.
3. 양쪽에서 찾은 모음을 교환한다.
4. 두 포인터를 안쪽으로 이동해 같은 과정을 반복한다.

안쪽 반복문의 조건에도 `left < right`를 넣었다. 한쪽 포인터가 다른 쪽을 지나친 뒤에도 계속 탐색하거나 불필요한 교환을 하지 않도록 하기 위해서다.

이 방식도 각 문자를 최대 한 번씩 확인하므로 시간 복잡도는 `O(n)`이다. 별도의 모음 위치 리스트는 사용하지 않지만, 파이썬 문자열을 수정하기 위해 `res = list(s)`를 만들므로 전체 공간 복잡도는 `O(n)`이다.

처음 풀이의 `loc`은 모음 위치가 눈에 보이기 때문에 동작을 이해하기 쉽다. 투 포인터 풀이는 같은 시간 복잡도를 유지하면서 모음 위치를 저장하는 리스트를 없앤다는 차이가 있다.

## 4. 스스로 묻고 답한 질문들

### Q. `cnt` 대신 `len(loc)`을 사용해도 될까?

`loc`을 빈 리스트로 만들고 모음을 찾을 때마다 `append()`한다면 가능하다.

```python
loc = []
loc.append(i)
```

이 경우 `len(loc)`가 실제로 찾은 모음의 개수다. 따라서 별도의 `cnt` 변수를 둘 필요가 없다.

반대로 문자열 길이에 맞춰 `loc`을 미리 만들면 사용하지 않은 `0`들이 남을 수 있다.

```python
loc = [0] * len(s)
```

이때 `len(loc)`은 모음 개수가 아니라 문자열의 길이이므로 반복 범위로 바로 사용할 수 없다.

### Q. 왜 `len(loc) - 1`만 쓰는 것이 아니라 `len(loc) - j - 1`을 사용할까?

`len(loc) - 1`은 항상 리스트의 마지막 인덱스다. 반복할 때마다 오른쪽에서 한 칸씩 안으로 이동하려면 현재 반복 번호인 `j`도 빼야 한다.

```python
loc[len(loc) - j - 1]
```

파이썬의 음수 인덱스를 사용하면 같은 표현을 더 간단하게 쓸 수 있다.

```python
loc[-j - 1]
```

### Q. `return res`를 그대로 사용하면 안 될까?

`res = list(s)`로 만들었다면 `res`의 타입은 문자열이 아니라 리스트다.

```python
["h", "o", "l", "l", "e"]
```

문제에서 요구하는 반환값은 문자열이므로 다음과 같이 합쳐야 한다.

```python
return "".join(res)
```

### Q. `"".join(res)`에서 앞의 `""`는 무엇을 의미할까?

`join()` 앞의 문자열은 각 원소 사이에 넣을 구분자다.

```python
"".join(["h", "i"])       # "hi"
" ".join(["hello", "me"]) # "hello me"
"-".join(["a", "b", "c"]) # "a-b-c"
```

`"".join(res)`는 각 문자 사이에 아무것도 넣지 않고 이어 붙인다는 뜻이다. 반면 Reverse Words 문제에서 사용한 `" ".join(words)`는 단어 사이에 공백 하나를 넣는다.

### Q. 모음 위치를 저장하는 풀이도 잘못된 풀이일까?

아니다. 모음 위치를 저장하는 풀이도 시간 복잡도가 `O(n)`이며 올바르게 동작한다. 투 포인터 방식은 모음 위치를 모두 저장하지 않고 발견하는 즉시 교환한다는 점에서 추가 자료구조를 하나 줄인 풀이로 볼 수 있다.

## 정리하며

Day 3에서는 문자열을 원하는 단위로 나눈 뒤 순서를 바꾸고 다시 합치는 과정을 연습했다. 단어 단위로 처리할 때는 `split()`과 `" ".join()`을 사용했고, 문자 단위로 수정할 때는 `list(s)`와 `"".join()`을 사용했다.

특히 파이썬 문자열은 내부 문자를 직접 수정할 수 없다는 점을 실제 타입 에러를 통해 확인했다. 또한 리스트의 마지막 원소를 가리키는 음수 인덱스와, 문자열 전체의 대칭 위치를 계산하는 식을 구분해야 했다.

처음 작성한 모음 위치 저장 방식도 올바른 풀이였고, 이후에는 같은 문제를 투 포인터로 다시 풀어보면서 중간 위치 배열 없이 양쪽에서 바로 탐색하는 방법까지 비교할 수 있었다.
