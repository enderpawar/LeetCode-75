# [LeetCode 75 Day 9] Binary Search Tree, Binary Search

LeetCode 75 아홉 번째 날에는 이진 탐색 트리에서 원하는 노드를 찾는 문제와, 숫자의 대소 관계를 이용해 정답을 찾는 문제를 풀었다.

두 문제 모두 현재 확인한 값을 기준으로 탐색할 범위를 한쪽으로 좁힌다. 다만 첫 번째 문제는 트리의 왼쪽 또는 오른쪽 자식으로 이동하고, 두 번째 문제는 `left`와 `right` 경계를 직접 변경한다. 이번에는 재귀 호출의 반환값을 바깥 호출까지 전달하는 방법과 이진 탐색에서 경계를 움직이는 방향을 중심으로 정리했다.

## 1. Search in a Binary Search Tree - 값의 대소 관계로 한쪽만 탐색하기

이진 탐색 트리의 루트 `root`와 정수 `val`이 주어졌을 때, 값이 `val`인 노드를 찾아 그 노드를 루트로 하는 서브트리를 반환하는 문제다. 해당 값이 트리에 없으면 `None`을 반환한다.

```python
# Definition for a binary tree node.
# class TreeNode(object):
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right


class Solution(object):
    def searchBST(self, root, val):
        if root is None:
            return None

        if root.val == val:
            return root

        if val < root.val:
            return self.searchBST(root.left, val)

        return self.searchBST(root.right, val)
```

이진 탐색 트리에서는 현재 노드를 기준으로 왼쪽 서브트리의 값은 더 작고, 오른쪽 서브트리의 값은 더 크다. 따라서 일반적인 DFS처럼 양쪽 자식을 모두 확인할 필요가 없다.

현재 노드의 값이 찾는 값과 같다면 그 노드 자체를 반환한다.

```python
if root.val == val:
    return root
```

문제에서 요구하는 것은 노드의 값이나 값을 담은 리스트가 아니라, 찾은 노드를 루트로 하는 서브트리다. `root`는 현재 노드와 그 아래의 자식들을 연결한 객체이므로 그대로 반환하면 된다.

찾는 값이 현재 값보다 작으면 왼쪽으로, 크면 오른쪽으로 이동한다.

```python
if val < root.val:
    return self.searchBST(root.left, val)

return self.searchBST(root.right, val)
```

처음에는 재귀 호출만 실행하면 안쪽 호출에서 찾은 노드가 자동으로 최종 결과가 될 것이라고 생각할 수 있다.

```python
self.searchBST(root.left, val)
```

하지만 안쪽 호출이 노드를 반환해도 바깥 호출이 그 값을 다시 반환하지 않으면 결과가 사라진다. 각 재귀 호출 앞에 `return`을 붙여야 가장 깊은 호출에서 찾은 노드가 이전 호출들을 거쳐 최초의 `searchBST()` 호출까지 전달된다.

탐색 중 `root`가 `None`이 되면 해당 방향에는 찾는 값이 없다는 의미이므로 `None`을 반환한다. 루트가 처음부터 비어 있는 경우도 같은 조건으로 처리된다.

트리의 높이를 `h`라고 하면 한 단계마다 자식 하나만 선택하므로 시간 복잡도는 `O(h)`이고, 재귀 호출 스택의 공간 복잡도도 `O(h)`다. 균형 잡힌 이진 탐색 트리에서는 `h = log n`이므로 둘 다 `O(log n)`이지만, 트리가 한쪽으로 치우친 최악의 경우에는 `O(n)`이다.

## 2. Guess Number Higher or Lower - API 응답에 따라 탐색 범위 줄이기

`1`부터 `n` 사이에서 미리 선택된 숫자를 맞히는 문제다. 숫자를 추측해 `guess(num)`에 전달하면 다음 결과 중 하나가 반환된다.

- `-1`: 추측한 숫자가 정답보다 크다.
- `1`: 추측한 숫자가 정답보다 작다.
- `0`: 추측한 숫자가 정답과 같다.

```python
# The guess API is already defined for you.
# def guess(num):


class Solution(object):
    def guessNumber(self, n):
        left = 1
        right = n

        while left <= right:
            answer = (left + right) // 2
            result = guess(answer)

            if result == 1:
                left = answer + 1
            elif result == -1:
                right = answer - 1
            else:
                return answer
```

처음 탐색 범위는 `1`부터 `n`까지다. 매 반복에서 범위의 중간값을 구하고, 그 값을 `guess()`에 전달한다.

```python
answer = (left + right) // 2
result = guess(answer)
```

파이썬 3에서 `/`는 나눗셈 결과를 실수로 만든다. 예를 들어 `5 / 2`는 `2.5`다. 이 문제에서는 정수만 추측해야 하므로 몫을 구하는 `//`를 사용한다.

API가 `1`을 반환하면 현재 추측값이 정답보다 작다는 뜻이다. 현재 값과 그보다 작은 수는 더 확인할 필요가 없으므로 다음 탐색의 왼쪽 경계를 `answer + 1`로 옮긴다.

```python
if result == 1:
    left = answer + 1
```

반대로 `-1`은 추측값이 정답보다 크다는 뜻이므로 오른쪽 경계를 `answer - 1`로 옮긴다.

```python
elif result == -1:
    right = answer - 1
```

구현하면서 이 두 방향을 반대로 적기도 했다. `-1`과 `1`을 단순히 왼쪽과 오른쪽에 대응시키기보다, API의 결과를 문장으로 풀어 쓰면 방향을 정하기 쉽다.

```text
추측값이 작다 → 정답은 더 큰 쪽에 있다 → left를 올린다
추측값이 크다 → 정답은 더 작은 쪽에 있다 → right를 내린다
```

또한 경계만 변경하고 `answer`를 반복문 밖에서 한 번만 계산하면 같은 숫자를 계속 추측하게 된다. 중간값 계산은 반드시 반복문 안에 있어야 변경된 `left`와 `right`가 다음 추측에 반영된다.

`guess(answer)`의 결과는 한 번만 구해 `result`에 저장했다. 같은 값을 여러 번 호출해도 결과는 같지만, 변수에 저장하면 API를 불필요하게 반복 호출하지 않고 각 조건의 의미도 더 분명하게 읽을 수 있다.

정답과 같아 `0`이 반환되면 `answer`를 반환한다. 문제에서 정답이 반드시 `1`부터 `n` 사이에 있다고 보장하므로 반복문 안에서 정답을 찾게 된다.

탐색 범위가 매번 절반으로 줄어들기 때문에 시간 복잡도는 `O(log n)`이다. 범위와 중간값을 저장하는 변수만 사용하므로 공간 복잡도는 `O(1)`이다.

## 3. 스스로 묻고 답한 질문들

### Q. BST에서도 왼쪽과 오른쪽을 모두 DFS로 탐색하면 안 될까?

모든 노드를 탐색하면 답을 찾을 수는 있지만 이진 탐색 트리의 정렬된 성질을 활용하지 못한다. 현재 값과 `val`을 비교하면 어느 방향에 답이 있을 수 있는지 바로 알 수 있으므로 한쪽만 탐색하면 된다.

균형 잡힌 트리에서 양쪽을 모두 확인하면 시간 복잡도가 `O(n)`이지만, 한쪽만 선택하면 `O(log n)`까지 줄일 수 있다.

### Q. 재귀 호출 앞의 `return`은 왜 필요할까?

재귀 함수의 각 호출은 서로 다른 함수 실행이다. 가장 안쪽 호출에서 `root`를 반환하더라도 바깥 호출이 그 반환값을 받기만 하고 다시 반환하지 않으면 최초 호출까지 전달되지 않는다.

```python
return self.searchBST(root.left, val)
```

이 코드는 재귀 호출의 결과를 현재 호출의 결과로 그대로 반환한다는 뜻이다.

### Q. 찾은 노드의 값을 리스트로 만들어 반환해야 하지 않을까?

LeetCode가 출력 예시를 배열처럼 보여주더라도 함수가 실제로 반환해야 하는 것은 `TreeNode` 객체다. 해당 노드를 반환하면 그 노드에 연결된 왼쪽과 오른쪽 자식도 함께 서브트리를 구성한다. LeetCode가 채점 과정에서 그 트리 구조를 배열 형태로 표현해 보여줄 뿐이다.

### Q. `/`와 `//`는 어떻게 다를까?

파이썬 3에서 `/`는 일반 나눗셈이고 결과가 항상 실수다. `//`는 몫을 구하는 연산자다.

```python
5 / 2   # 2.5
5 // 2  # 2
```

이진 탐색에서는 정수 인덱스나 정수 후보가 필요하므로 `(left + right) // 2`처럼 작성한다. 다만 `//`는 단순히 소수점만 잘라내는 연산이라기보다 내림 나눗셈이다. 그래서 음수에서는 `-5 // 2`가 `-3`이 된다. 이번 문제의 범위는 양수이므로 이 차이가 결과에 영향을 주지는 않는다.

### Q. `guess()`가 `-1`을 반환하면 왜 왼쪽이 아니라 오른쪽 경계를 움직일까?

`-1`은 이동 방향을 직접 지시하는 값이 아니라, 내가 전달한 숫자가 정답보다 크다는 뜻이다. 정답은 현재 추측값의 왼쪽, 즉 더 작은 범위에 있으므로 `right = answer - 1`로 변경해야 한다.

### Q. `while left < right`와 `while left <= right` 중 무엇을 써야 할까?

현재 코드는 중간값이 정답인지 반복문 안에서 직접 검사하는 형태다. `left == right`일 때도 마지막 후보 하나를 확인해야 하므로 `left <= right`를 사용했다. 경계를 갱신할 때 현재 중간값을 제외하도록 `answer + 1`과 `answer - 1`을 사용하는 것도 중요하다.

## 정리하며

이번 두 문제는 자료구조가 트리와 숫자 범위로 서로 달랐지만, 현재 값을 기준으로 가능성이 없는 절반을 버린다는 점은 같았다. BST에서는 `val`과 `root.val`을 비교해 자식 하나만 선택했고, 숫자 맞히기에서는 `guess()`의 결과에 따라 `left` 또는 `right`를 옮겼다.

구현에서는 탐색 아이디어뿐 아니라 결과를 다음 단계로 정확히 전달하는 일이 중요했다. 재귀 풀이에서는 안쪽 호출의 결과가 사라지지 않도록 `return`을 붙여야 했고, 반복문 풀이에서는 변경된 경계를 반영해 중간값을 매번 다시 계산해야 했다. 앞으로 이진 탐색을 구현할 때는 중간값 자체보다 각 비교 결과가 어떤 범위를 제외하는지 문장으로 먼저 확인해보면 경계 방향을 덜 헷갈릴 것 같다.
