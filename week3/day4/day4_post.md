# [LeetCode 75 Day 18] 394. Decode String

Day 16, 17에서 스택과 트리를 각각 한 번씩 훑고 다시 스택 파트로 돌아왔다. 앞의 두 스택 문제(Removing Stars, Asteroid Collision)는 "가장 최근 것 하나만 보면 되는가"를 판단하는 문제였는데, 이번 문제는 성격이 달랐다. 괄호가 중첩되기 때문에 **작업 중이던 것을 잠시 미뤄뒀다가 나중에 이어서 해야 하는** 상황이 처음으로 등장했다.

이번 목표는 정답 코드를 외우는 게 아니라 스택 감각을 익히는 것이었기 때문에, 처음 떠올렸던 재귀 풀이는 일부러 미뤄두고 스택으로만 밀어붙였다. 그 과정에서 첫 접근이 왜 통째로 무너졌는지가 이 문제에서 가장 크게 남은 부분이라 그 이야기에 무게를 뒀다.

## 1. Decode String - 닫는 괄호를 계산 신호로 삼기

`k[encoded_string]` 형식으로 인코딩된 문자열이 주어진다. 대괄호 안의 문자열을 `k`번 반복해서 펼친 결과를 반환하는 문제다. 괄호는 항상 올바르게 짝지어져 있고, 원래 문자열에는 숫자가 없으며 숫자는 오직 반복 횟수로만 등장한다. 대신 `3[a2[c]]`처럼 괄호가 중첩될 수 있다.

```python
class Solution(object):
    def decodeString(self, s):
        """
        :type s: str
        :rtype: str
        """

        stack = []

        for c in s:
            if c != ']':
                stack.append(c)

            else:
                # 1. '[' 전까지 문자열 꺼내기
                tmp = ""

                while stack[-1] != '[':
                    tmp = stack.pop() + tmp

                # 2. '[' 제거
                stack.pop()

                # 3. 반복 횟수 꺼내기
                num = ""

                while stack and stack[-1].isdigit():
                    num = stack.pop() + num

                # 4. 문자열 반복
                decoded = tmp * int(num)

                # 5. 다시 stack에 넣기
                stack.append(decoded)

        return "".join(stack)
```

문자열을 왼쪽에서 오른쪽으로 한 글자씩 읽되, `]`가 아닌 글자는 전부 판단을 보류하고 그냥 쌓는다. 숫자든 `[`든 일반 문자든 그 시점에는 아직 확정할 수 있는 게 없기 때문이다. 그러다 `]`를 만나는 순간이 **"구간 하나가 방금 완성됐다"는 신호**가 된다. 이 풀이에서 pop이 일어나는 조건은 오직 이 하나뿐이고, 그래서 코드가 단순해진다.

`]`를 만나면 그 자리에서 구간 하나를 끝까지 처리한다. 먼저 `[`가 나올 때까지 꺼내서 반복할 문자열을 복원한다. 스택은 가장 최근 것부터 나오므로, 가장 가까운 `[`가 자동으로 짝이 맞는 여는 괄호가 된다. 괄호 짝 맞추기를 따로 신경 쓸 필요가 없다는 게 여기서 스택을 쓰는 가장 큰 이득이었다.

```python
while stack[-1] != '[':
    tmp = stack.pop() + tmp
```

꺼낸 글자를 `tmp` 뒤가 아니라 **앞**에 붙이는 이유는 pop 순서가 역순이기 때문이다. 스택에 `a`, `b`, `c`가 있으면 pop 순서는 `c`, `b`, `a`인데, 앞에 붙이면 `"c"` → `"bc"` → `"abc"`가 되어 원래 순서가 복원된다.

그다음 `[`를 버리고, 그 앞에 붙어 있던 숫자를 꺼낸다. `while`로 감싼 이유는 `100[a]`처럼 반복 횟수가 두 자리 이상일 수 있기 때문이고, 숫자를 앞에 붙이는 것도 같은 이유다. pop 순서가 `0`, `0`, `1`이라 앞에 붙여야 `"100"`이 된다. `isdigit()`으로 멈춰야 하는 것도 중요한데, `a3[b]`처럼 숫자 앞에 일반 문자가 붙어 있을 수 있어서 숫자가 아닌 걸 만나면 즉시 멈춰야 한다.

마지막 두 줄이 이 풀이의 핵심이다.

```python
decoded = tmp * int(num)
stack.append(decoded)
```

완성된 결과를 밖으로 내보내지 않고 **다시 스택에 되돌려 넣는다.** `2[c] → "cc"`는 답이 아니라 바깥 구간이 쓸 재료이기 때문이다. `3[a2[c]]`를 추적해보면 이게 왜 필요한지 바로 보인다.

```text
['3', '[', 'a', '2', '[', 'c']   ← 첫 번째 ']'을 만나기 직전
['3', '[', 'a', 'cc']            ← "c" * 2 를 다시 넣음
                                    두 번째 ']' 처리 시 'cc', 'a'를 꺼내 "acc"
"accaccacc"                      ← "acc" * 3
```

여기서 스택 안의 원소가 전부 한 글자가 아니게 된다는 점이 처음엔 어색했는데, `"cc" != '['`이고 `"cc".isdigit()`도 `False`라서 두 while 조건이 그대로 성립한다. 마지막에 `"".join(stack)`으로 남은 조각들을 이어붙이면 끝난다. `2[abc]3[cd]ef`라면 마지막 스택은 `["abcabc", "cdcdcd", 'e', 'f']`가 된다.

풀면서 걸렸던 부분은 다음과 같았다.

- **처음 접근을 통째로 버려야 했다.** 처음에는 `for c in s: stack.append(c)`로 전부 쌓아둔 다음 pop으로 순회했는데, 이건 스택을 쓴 게 아니라 그냥 `reversed(s)`로 거꾸로 읽은 것이었다. `k[...]`는 숫자가 앞에 있어서 거꾸로 읽으면 내용을 다 모은 뒤에야 반복 횟수를 알게 되고, 그 사이에 안쪽 괄호가 끼어들면 감당이 안 된다. 스택 문제에서 "일단 전부 push"는 거의 항상 불필요하고, 한 글자씩 읽으면서 그때그때 push/pop을 판단하는 게 기본 형태라는 걸 이번에 알았다.
- **중첩을 플래그로 표현하려 했다.** `rpt_state`라는 bool 하나와 `tmp_stack` 하나로 상태를 관리하려 했는데, `3[a2[c]]`에는 동시에 살아 있는 구간이 두 개다. 바깥 구간이 모아둔 `"a"`를 어딘가 보관해뒀다가 안쪽이 끝난 뒤 꺼내 써야 하는데, 임시 저장소가 하나뿐이라 두 구간의 문자가 섞여버렸다. `rcd_num`으로 괄호 깊이를 세는 방향까지는 맞았지만, 깊이만 알고 각 깊이의 데이터는 갖고 있지 않았던 게 문제였다.
- **`IndexError: pop from empty list`.** `tmp_stack = []`를 for문 안에 선언해서 매 반복마다 초기화되고 있었다. 초기화는 루프 밖, 갱신은 루프 안이라는 당연한 규칙을 놓쳤다.
- **`is`와 `==`를 혼동했다.** `if c is ']'`, `if rcd_num is not 0`처럼 썼는데, `is`는 값이 아니라 객체 동일성을 비교한다. 더 골치 아픈 건 CPython이 한 글자 문자열과 작은 정수를 캐싱해서 이게 **우연히 True로 동작한다**는 점이다. 틀린 코드가 잘 돌아가다가 큰 수에서 조용히 어긋난다. Python 3.8부터는 `SyntaxWarning: "is" with a literal` 경고가 뜬다.
- **pop을 k번 하는 것과 문자열을 k번 반복하는 걸 헷갈렸다.** `for i in range(int(c)): print(tmp_stack.pop())`이라고 썼는데, `tmp_stack`에 `'c'` 하나뿐인데 두 번 pop하니 당연히 터진다. 필요한 건 `"c" * 2`였다. 여기에 더해 `print`로 흘려보낸 것도 결정적이었다. 출력해버리면 그 결과를 바깥 구간이 다시 쓸 수 없다.

각 문자가 스택에 한 번 들어갔다 나오므로 골격 자체는 결과 길이에 비례한다. 다만 `tmp = stack.pop() + tmp`가 매번 새 문자열을 만들기 때문에, 한 구간의 길이가 `L`이면 그 구간을 모으는 데만 `O(L²)`이 든다. 결과 문자열 길이를 `m`이라 하면 시간 복잡도는 최악의 경우 `O(m²)`, 공간 복잡도는 `O(m)`이다.

### 더 개선한다면

아쉬운 지점이 두 개 있는데 원인은 하나다. 문자를 스택에 낱개로 쌓아뒀기 때문에, 나중에 그걸 되돌리느라 `+` 연산을 반복하고 있다. 문자열을 한 글자씩 앞에 붙이는 것도, 숫자를 한 글자씩 꺼내 `int()`로 되돌리는 것도 전부 "낱개로 쌓았으니 낱개로 복원해야 한다"의 결과다. 애초에 낱개로 쌓지 않으면 둘 다 사라진다.

그러려면 스택에 무엇을 넣을지를 다시 정해야 한다. `[`를 만났을 때 진짜로 보관해야 하는 건 글자가 아니라 **"지금까지 만들던 문자열"과 "곧 적용할 반복 횟수"** 두 가지다. 이 둘을 각각 다른 스택에 대피시키면, 스택에는 `[`도 숫자 글자도 들어가지 않는다.

```python
class Solution(object):
    def decodeString(self, s):
        """
        :type s: str
        :rtype: str
        """

        num_stack = []   # 아직 반복을 못 끝낸 k들
        str_stack = []   # 안쪽 구간을 처리하는 동안 대피시켜 둔 바깥 문자열
        cur = ""         # 지금 만들고 있는 문자열
        num = 0          # 지금 읽고 있는 숫자

        for char in s:
            if char.isdigit():
                num = num * 10 + int(char)

            elif char == '[':
                num_stack.append(num)
                str_stack.append(cur)
                num = 0
                cur = ""

            elif char == ']':
                cur = str_stack.pop() + cur * num_stack.pop()

            else:
                cur += char

        return cur
```

`num = num * 10 + int(char)`는 `100`을 읽을 때 `1` → `10` → `100`으로 자릿수를 올리는 방식이라, 나중에 숫자를 다시 긁어모을 필요가 없다. `]`를 만나면 대피시켜 둔 바깥 문자열을 꺼내 `cur * k`를 이어붙이기만 하면 되므로, 앞에 붙이며 순서를 복원하던 while 루프도 통째로 사라진다. `3[a2[c]]`를 따라가면 두 번의 `[`에서 `str_stack`이 `["", "a"]`, `num_stack`이 `[3, 2]`가 되고, 안쪽 `]`에서 `"a" + "c" * 2 = "acc"`, 바깥 `]`에서 `"" + "acc" * 3 = "accaccacc"`가 나온다.

시간 복잡도는 `O(m)`, 공간 복잡도는 `O(m)`으로 줄었다. 대가라면 관리할 변수가 하나에서 네 개로 늘어난 것인데, 대신 `stack[-1]`을 들여다보는 조건 검사가 없어져서 빈 스택을 걱정할 일도 함께 없어졌다. 정리해보니 처음 접근에서 내가 만들려던 게 사실 이 `cur`와 `num`이었다. 그때는 그걸 한 벌만 갖고 있었고, 중첩 때문에 여러 벌이 필요했던 것뿐이다.

## 2. 스스로 묻고 답한 질문들

### Q. 스택에 전부 넣고 pop하는 것과 `reversed(s)`로 도는 건 정확히 뭐가 다른가?

다르지 않다. `for c in s: stack.append(c)`로 전부 넣은 뒤 `stack.pop()`을 반복하면 결과적으로 `for c in reversed(s)`와 동일하다. 그래서 첫 접근은 스택 자료구조의 이점을 하나도 쓰지 못했다. 스택이 힘을 발휘하는 건 push와 pop이 **입력 순서와 무관한 시점에** 섞여 일어날 때다. 이번 풀이에서는 `]`를 만난 순간에만 pop이 일어나고 나머지는 계속 push인데, 그 비대칭이 곧 중첩 처리다.

### Q. `tmp = stack.pop() + tmp`에서 왜 앞에 붙이나?

스택이 LIFO라 pop이 역순으로 나오기 때문이다. `abc`가 쌓여 있으면 `c`, `b`, `a` 순으로 나오는데 뒤에 붙이면 `"cba"`가 된다. 앞에 붙이면 `"c"` → `"bc"` → `"abc"`로 원래 순서가 복원된다. 숫자를 꺼내는 `num = stack.pop() + num`도 완전히 같은 이유다. `12[a]`라면 pop 순서가 `2`, `1`이라 앞에 붙여야 `"12"`가 된다.

### Q. `while stack and stack[-1].isdigit()`에서 `stack and`는 왜 필요한가?

`3[a]`처럼 숫자가 문자열 맨 앞에 있으면, `'3'`을 꺼낸 순간 스택이 비어버린다. 그 상태에서 `stack[-1]`을 보면 `IndexError`가 난다. 파이썬의 `and`는 왼쪽이 거짓이면 오른쪽을 아예 평가하지 않기 때문에(단축 평가), `stack`을 앞에 두면 빈 리스트일 때 `stack[-1]`이 실행되지 않는다. 순서를 바꿔 쓰면 그대로 터진다.

### Q. 스택에 여러 글자짜리 문자열을 넣어도 괜찮은가?

괜찮다. 오히려 그게 이 풀이의 핵심이다. 스택을 "문자를 담는 통"이 아니라 "보류 중인 조각들의 목록"으로 보면 조각의 길이는 상관이 없다. 조건 검사도 그대로 성립하는데, `"cc" != '['`이고 `"cc".isdigit()`은 `False`이기 때문이다. 원래 문자열에 숫자가 없다는 문제의 제약 덕분에, 복호화된 조각이 `isdigit()`을 잘못 통과할 일도 없다.

### Q. 재귀로 풀면 어떻게 되나?

의사코드 단계에서 먼저 떠올렸던 방향이고 실제로도 자연스럽다. `[`에서 재귀로 들어가고 `]`에서 반환하면 되는데, 문제는 재귀 안에서 문자열을 어디까지 소비했는지를 호출한 쪽에 알려줘야 한다는 점이다. `(문자열, 다음_인덱스)`를 함께 반환하거나, 인덱스를 `nonlocal`로 공유하는 두 가지 방법이 있다. 사실 위의 2-스택 풀이에서 `str_stack`과 `num_stack`이 하는 일이, 재귀에서는 호출 스택이 자동으로 해주는 일과 정확히 같다. 재귀 버전은 다음에 직접 구현해보기로 했다.

## 정리하며

이번 문제에서 얻은 건 문법보다 관점 쪽이다. 스택을 "값을 담는 통"으로만 보고 있었는데, 중첩된 구조에서는 스택이 **미뤄둔 작업의 목록**이라는 걸 알게 됐다. 그래서 스택 문제를 볼 때 던질 질문도 하나 생겼다. "안쪽 일을 하는 동안, 바깥 일의 무엇을 기억해둬야 하지?" 이번 문제의 답은 만들던 문자열과 반복 횟수 두 가지였고, 그걸 몇 벌 들고 있어야 하는지가 곧 괄호 깊이였다.

패턴 자체는 이렇게 정리해뒀다. 닫는 기호가 아니면 push, 닫는 기호를 만나면 여는 기호까지 pop해서 계산하고, **결과를 다시 push한다.** 마지막 "다시 push"가 중첩을 처리하는 지점이다. 처음 코드에서 `print`를 썼던 자리가 정확히 여기였다.
