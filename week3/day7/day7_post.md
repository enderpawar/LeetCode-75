# [LeetCode 75 Day 21] 649. Dota2 Senate & 236. Lowest Common Ancestor of a Binary Tree

Day 21에서는 순서가 반복되는 시뮬레이션 문제와, 두 노드의 정보를 아래에서 위로 합치는 이진 트리 문제를 풀었다. Dota2 Senate는 문자열을 한 번 훑어서 정당별 인원수를 세면 될 것처럼 보였지만, 실제로는 의원들이 순서대로 상대의 권리를 박탈하고 다음 라운드까지 이어가야 했다. Lowest Common Ancestor는 왼쪽과 오른쪽 서브트리에서 찾은 결과가 현재 노드에서 어떤 의미가 되는지 정리하는 것이 중요했다.

두 문제의 모양은 다르지만, 현재 위치의 값만 보고 결정하면 부족하다는 공통점이 있었다. 첫 문제에서는 다음 라운드까지 이어지는 행동 순서를 보존해야 했고, 두 번째 문제에서는 서브트리가 `p`와 `q` 중 무엇을 찾았는지 부모에게 전달해야 했다.

## 1. Dota2 Senate - 순서대로 상대의 권리를 박탈하기

`R`은 Radiant, `D`는 Dire 소속 의원을 뜻한다. 의원들은 문자열에 적힌 순서대로 행동하며, 자기 차례가 오면 상대 정당 의원 한 명의 현재 및 이후 라운드 권리를 박탈할 수 있다. 한 정당의 의원만 남으면 그 정당이 승리한다.

```python
class Solution:
    def predictPartyVictory(self, senate: str) -> str:
        balance = 0

        while 'R' in senate and 'D' in senate:
            next_round = ''

            for party in senate:
                if party == 'R':
                    if balance >= 0:
                        next_round += 'R'
                    balance += 1
                else:
                    if balance <= 0:
                        next_round += 'D'
                    balance -= 1

            senate = next_round

        return 'Radiant' if senate[0] == 'R' else 'Dire'
```

`balance`는 아직 사용되지 않은 권리 박탈 횟수의 차이다. 양수라면 Radiant가 Dire를 박탈할 권리가 남아 있고, 음수라면 Dire가 Radiant를 박탈할 권리가 남아 있다.

현재 의원이 `R`일 때 `balance`가 음수라면 앞선 Dire 의원이 만들어둔 박탈 권한이 있다는 뜻이므로 이 의원은 다음 라운드로 가지 못한다. 반대로 `balance >= 0`이라면 자신을 막는 권한이 없으므로 `next_round`에 살아남는다. 그 뒤 `balance += 1`을 수행하는 이유는, 살아남든 탈락하든 현재 `R`을 처리하면서 Dire 쪽 권리와의 차이가 한 칸 Radiant 방향으로 이동하기 때문이다. `D`도 반대 방향으로 같은 방식으로 처리한다.

중요한 점은 한 라운드가 끝나도 `balance`를 `0`으로 초기화하지 않는 것이다. 마지막에 행동한 의원이 만든 박탈 권한은 다음 라운드의 첫 번째 의원에게 적용된다. `next_round`에는 이번 라운드에서 권리를 잃지 않은 의원만 남기고, 한 정당만 남을 때까지 같은 과정을 반복한다.

`RRDDD`를 따라가 보면 첫 라운드에서 앞의 `R` 두 명이 `D` 두 명을 제거한다. 마지막 `D`는 살아남으면서 다음 라운드의 `R` 한 명을 제거할 권한을 만든다. 다음 라운드에는 `RRD`가 남고, 첫 번째 `R`이 제거된 뒤 두 번째 `R`이 마지막 `D`를 제거하므로 결과는 `Radiant`다.

처음 접근에서 걸렸던 부분은 다음과 같았다.

- `past_party` 하나로 직전 정당과 현재 정당만 비교했다. 이 방식은 탈락한 의원도 다음 의원에게 영향을 주는 것처럼 처리하며, 문자열 끝에서 처음으로 이어지는 다음 라운드도 표현하지 못했다.
- Radiant와 Dire의 수가 같으면 `Dire`를 반환하도록 작성했다. 하지만 이 문제는 동시 다수결이 아니라 순차 행동이므로, 같은 인원이라도 먼저 행동하는 쪽이 이길 수 있다.
- 문자열을 비교할 때 `is`, `is not`을 사용해 `SyntaxWarning`이 발생했다. 문자열의 값은 `==`, `!=`로 비교해야 한다.
- 테스트 코드를 클래스 안에 들여써서 클래스 정의가 끝나기 전에 `Solution()`을 참조했다. 테스트 코드는 클래스 정의가 끝난 뒤 들여쓰기 없이 작성해야 한다.

라운드마다 현재 문자열을 다시 훑고, 최소 한 명이 탈락한다고 보면 순회 자체의 최악 시간 복잡도는 `O(n²)`이다. 여기에 Python 문자열은 변경할 수 없기 때문에 `next_round += party`가 기존 문자열을 반복해서 복사할 수 있다는 비용도 있다. 공간 복잡도는 다음 라운드 문자열을 저장하므로 `O(n)`이다.

### 더 개선한다면

현재 풀이는 `balance` 하나로 권리 차이를 표현해서 이해하기는 쉽지만, 매 라운드마다 생존자 문자열을 새로 만든다. 의원의 원래 순서를 인덱스로 저장하면 문자열을 반복해서 만들지 않아도 된다. Radiant와 Dire의 인덱스를 각각 큐에 넣고, 두 큐의 맨 앞 인덱스를 비교해 더 먼저 행동하는 의원만 다음 라운드로 보낸다.

```python
from collections import deque


class Solution:
    def predictPartyVictory(self, senate: str) -> str:
        radiant = deque()
        dire = deque()
        senate_count = len(senate)

        for index, party in enumerate(senate):
            if party == 'R':
                radiant.append(index)
            else:
                dire.append(index)

        while radiant and dire:
            radiant_index = radiant.popleft()
            dire_index = dire.popleft()

            if radiant_index < dire_index:
                radiant.append(radiant_index + senate_count)
            else:
                dire.append(dire_index + senate_count)

        return 'Radiant' if radiant else 'Dire'
```

두 의원 중 인덱스가 작은 의원이 먼저 행동해 상대를 제거한다. 살아남은 의원의 인덱스에 전체 의원 수 `n`을 더해 다시 큐에 넣으면, 그 의원의 다음 라운드 차례가 기존 의원들 뒤에 배치된다. 한 번의 대결마다 반드시 한 의원이 제거되므로 시간 복잡도는 `O(n)`, 두 큐에 전체 인덱스를 저장하므로 공간 복잡도는 `O(n)`이다. 문자열 방식보다 빠르지만, `balance` 하나만 사용한 코드보다 자료구조의 동작을 이해해야 한다는 부담이 있다.

## 2. Lowest Common Ancestor of a Binary Tree - 두 서브트리의 탐색 결과 합치기

이진 트리와 두 노드 `p`, `q`가 주어질 때 두 노드의 가장 낮은 공통 조상을 찾는 문제다. 여기서 노드는 자기 자신의 자손으로도 취급하므로, `p`가 `q`의 조상이라면 `p` 자체가 정답이 된다.

```python
class Solution:
    def lowestCommonAncestor(
        self,
        root: 'TreeNode',
        p: 'TreeNode',
        q: 'TreeNode',
    ) -> 'TreeNode':
        def dfs(node: 'TreeNode'):
            if node is None:
                return None

            left = dfs(node.left)
            right = dfs(node.right)

            if left and right:
                return node

            if node == p or node == q:
                return node

            return left or right

        return dfs(root)
```

`dfs(node)`는 현재 서브트리에서 `p`, `q` 또는 이미 발견한 LCA를 찾아 부모에게 반환한다. 왼쪽과 오른쪽 호출이 모두 노드를 반환했다면 `p`와 `q`가 현재 노드를 기준으로 서로 다른 방향에 있다는 뜻이므로 현재 노드가 LCA다. 한쪽만 값을 반환했다면 찾은 노드를 그대로 위로 올린다.

현재 노드가 `p`나 `q`인 경우도 중요하다. 예를 들어 `p`가 `q`의 조상이라면 한쪽 서브트리에서 `q`를 찾더라도 현재 노드가 `p`이므로 `p`를 반환한다. 문제에서 노드 자신도 자신의 자손으로 취급한다는 조건이 이 분기에 반영되어 있다.

후위 순회를 사용하는 이유는 현재 노드가 답인지 판단하기 전에 왼쪽과 오른쪽에 무엇이 있는지 먼저 알아야 하기 때문이다. 자식 호출의 결과를 받은 다음 현재 노드를 처리해야 두 노드가 갈라지는 가장 낮은 지점을 잡을 수 있다.

풀면서 확인한 부분은 다음과 같았다.

- 처음에는 탐색 완료 여부를 나타내는 별도 상태가 필요한지 고민했지만, 반환값 자체에 `None`, `p`, `q`, LCA라는 의미를 담을 수 있었다.
- 왼쪽 자식 하나만 확인해서는 두 노드가 서로 다른 서브트리에 있는 경우를 판별할 수 없다. 왼쪽과 오른쪽 결과를 모두 받아야 한다.
- 로컬 테스트에서 LeetCode의 배열 표현인 `[3, 5, 1, ...]`과 정수 `p = 5`, `q = 1`을 함수에 그대로 넘겼다. 함수는 실제 `TreeNode` 객체를 받으므로 로컬에서도 노드를 생성하고 서로 연결해야 한다.
- 테스트 코드는 `None`을 출력했지만 재귀 로직이 틀린 것이 아니라 테스트 데이터의 자료형이 잘못된 것이었다.

모든 노드를 최대 한 번씩 방문하므로 시간 복잡도는 `O(n)`이다. 공간 복잡도는 재귀 호출 스택에 사용되는 `O(h)`이며, `h`는 트리의 높이다. 한쪽으로 치우친 트리에서는 `O(n)`, 균형 트리에서는 `O(log n)`이다.

### 더 개선한다면

현재 풀이는 짧고 이미 최적 시간 복잡도인 `O(n)`이라 더 빠르게 만들 필요는 없다. 다만 `left`나 `right`가 반환한 노드가 `p`인지, `q`인지, 이미 계산된 LCA인지가 같은 `TreeNode` 반환값 안에 숨어 있다. 비트마스크를 사용하면 각 서브트리에서 무엇을 발견했는지 상태를 명시적으로 표현할 수 있다.

```python
class Solution:
    def lowestCommonAncestor(
        self,
        root: 'TreeNode',
        p: 'TreeNode',
        q: 'TreeNode',
    ) -> 'TreeNode':
        answer = None

        def dfs(node: 'TreeNode') -> int:
            nonlocal answer

            if node is None:
                return 0

            state = dfs(node.left) | dfs(node.right)

            if node is p:
                state |= 1
            if node is q:
                state |= 2

            if state == 3 and answer is None:
                answer = node

            return state

        dfs(root)
        return answer
```

`0b01`, 즉 `1`은 `p`를 찾았다는 뜻이고, `0b10`, 즉 `2`는 `q`를 찾았다는 뜻이다. 두 상태를 비트 OR 연산으로 합쳐 `0b11`, 즉 `3`이 되면 현재 서브트리에 두 노드가 모두 있다. 후위 순회에서 처음 `3`이 되는 가장 아래쪽 노드가 LCA이므로 `answer`가 아직 없을 때만 저장한다.

시간 복잡도와 재귀 공간 복잡도는 원래 풀이와 같은 `O(n)`, `O(h)`다. 두 노드가 트리에 모두 존재한다는 LeetCode 조건에서는 원래 풀이가 더 짧고 파이썬답다. 비트마스크 버전의 장점은 상태의 의미가 숫자로 분리되고, 두 노드가 모두 발견되지 않았다면 `answer`가 `None`으로 남아 입력 조건을 더 명확히 검증할 수 있다는 점이다.

여기서 비트마스크는 세그먼트 트리와 직접 관련된 기법은 아니다. 단지 두 개의 참/거짓 상태를 정수의 서로 다른 비트에 저장한 것이다. 같은 트리에서 LCA 질의를 매우 많이 처리해야 한다면 Euler Tour로 트리를 배열처럼 펼친 뒤 깊이의 최솟값을 구하는 RMQ 세그먼트 트리나 Binary Lifting을 고려할 수 있다. 하지만 이 문제처럼 한 번만 묻는 경우에는 전처리와 추가 메모리가 오히려 불필요하다.

## 3. 스스로 묻고 답한 질문들

### Q. 양쪽의 남은 의원 수가 같으면 왜 무승부가 아닌가?

이 문제는 모든 의원이 동시에 표를 던지는 방식이 아니다. `RD`라면 인원은 1대 1이지만 `R`이 먼저 `D`의 권리를 박탈하므로 Radiant가 이긴다. 반대로 `DR`에서는 Dire가 이긴다. 따라서 인원수가 같다는 사실만으로는 승자를 정할 수 없고, 현재 행동 순서를 함께 봐야 한다.

### Q. `balance == 0`인데 왜 현재 의원을 살려두는가?

`balance == 0`은 양 정당의 전체 인원이 같다는 뜻이 아니라, 지금까지 쌓여 있는 미사용 박탈 권한이 없다는 뜻이다. 현재 의원을 막는 상대 권한이 없으므로 그 의원은 정상적으로 행동하고 다음 라운드에도 살아남는다. 그 의원이 행동하면서 상대를 제거할 권한 하나가 새로 만들어진다.

### Q. 라운드가 끝날 때 `balance`를 초기화하면 왜 안 되는가?

투표 순서는 문자열 끝에서 종료되지 않고 다시 처음으로 이어진다. 마지막 `D`가 `R`을 제거할 권한을 얻었다면 그 대상은 다음 라운드 앞쪽의 `R`이 될 수 있다. 라운드마다 `balance`를 초기화하면 이 권한이 사라져 실제 진행과 달라진다.

### Q. `is`와 `==`는 무엇이 다른가?

`==`는 두 값의 내용이 같은지 비교하고, `is`는 두 변수가 메모리에서 같은 객체를 가리키는지 비교한다. 문자열 리터럴은 실행 환경에 따라 같은 객체로 재사용될 수도 있어서 `is` 비교가 우연히 동작하는 것처럼 보일 수 있지만, 값 비교를 보장하지 않는다. 따라서 `party == 'R'`처럼 작성해야 한다. 반대로 LCA 문제의 `node is p`는 값이 같은 노드가 아니라 문제에서 전달받은 바로 그 노드 객체인지 확인하려는 것이므로 객체 동일성 비교가 잘 맞는다.

### Q. 큐에서 살아남은 의원의 인덱스에 왜 `n`을 더하는가?

현재 라운드에서 인덱스가 `1`인 의원이 살아남았다면 다음 행동은 한 바퀴를 돈 뒤다. 이를 `1 + n`으로 표현하면 아직 행동하지 않은 현재 라운드 의원보다 뒤에, 다음 라운드의 올바른 순서로 배치할 수 있다. 실제 문자열을 회전시키지 않고도 계속 증가하는 인덱스로 원형 순서를 표현하는 방법이다.

### Q. LCA 풀이에서 `left`와 `right`가 모두 존재하면 왜 현재 노드가 정답인가?

왼쪽과 오른쪽 DFS는 각 서브트리에서 찾은 `p`, `q` 또는 LCA를 반환한다. 양쪽이 모두 값을 반환했다는 것은 목표 노드들이 현재 노드를 기준으로 서로 다른 방향에 있다는 뜻이다. 두 경로가 처음 합쳐지는 곳이 현재 노드이므로 더 아래에서는 둘의 공통 조상이 될 수 없다.

### Q. `p`가 `q`의 조상이라면 왜 `p`가 반환되는가?

`p`의 자식 방향을 탐색해 `q`를 찾더라도 현재 노드를 확인하는 분기에서 `node == p`가 참이 된다. 문제에서는 자기 자신도 자신의 자손으로 인정하므로, `p`는 자신과 아래의 `q`를 모두 포함하는 가장 낮은 공통 조상이다.

### Q. 비트마스크와 세그먼트 트리는 같은 방식인가?

아니다. 이 풀이의 비트마스크는 `p를 찾음`, `q를 찾음`이라는 두 상태를 정수의 두 비트에 압축하는 표현 방법이다. 세그먼트 트리는 배열 구간의 최솟값이나 합 같은 질의를 빠르게 처리하는 자료구조다. LCA에서도 Euler Tour와 깊이 배열을 만든 뒤 구간 최소 깊이를 찾는 용도로 세그먼트 트리를 사용할 수 있지만, 같은 트리에 대한 질의가 반복될 때 전처리 비용을 나누어 쓰기 위한 방법이다. 단일 질의인 236번에서는 DFS 한 번이 더 단순하다.

## 정리하며

두 문제 모두 현재 위치 하나만 보는 대신, 이후 판단에 필요한 상태를 어떤 형태로 보존할지가 중요했다. Dota2 Senate에서는 `RRDDD`를 직접 따라가며 탈락한 의원은 이후 행동할 수 없고 남은 박탈 권한은 다음 라운드까지 이어진다는 점을 확인했다. 같은 수의 의원이 남아도 행동 순서에 따라 승자가 달라지기 때문에 단순 카운트만으로는 해결할 수 없었다.

LCA에서는 왼쪽과 오른쪽 DFS가 찾은 노드를 반환값으로 올려보내고, 두 결과가 만나는 가장 낮은 지점을 답으로 삼았다. 비트마스크로 바꾸어보니 반환값에 숨어 있던 `p 발견`, `q 발견` 상태가 `1`, `2`, `3`으로 명시됐다. 다만 상태를 더 자세히 표현할 수 있다고 해서 항상 더 나은 코드는 아니며, 문제 조건이 보장된다면 원래 재귀 풀이가 더 짧고 충분히 효율적이라는 점도 함께 정리했다.

결국 원형 시뮬레이션에서는 다음 행동 순서를, 트리 후위 순회에서는 서브트리에서 찾은 정보를 잃지 않고 전달해야 했다. 큐와 비트마스크는 서로 다른 자료구조와 표현이지만, 둘 다 다음 단계의 판단에 필요한 상태를 보존한다는 역할을 했다.
