# [LeetCode 75 Day 23] Binary Search Tree, DFS

Day 23에서는 이진 탐색 트리에서 특정 값을 가진 노드를 삭제하는 문제를 풀었다. 처음에는 BST의 대소 관계를 이용해 `key`를 찾는 과정부터 DFS로 작성하면 되겠다고 생각했다. 탐색 자체보다 어려웠던 부분은 삭제할 노드를 찾은 뒤 그 자리를 어떤 노드로 이어야 하는지 정리하는 일이었다.

이번 문제를 통해 BST에서 노드를 삭제할 때는 자식 수에 따라 경우를 나눠야 한다는 점과, 재귀 함수가 반환한 서브트리의 새 루트를 부모에게 다시 연결해야 한다는 점을 정리했다.

## 1. Delete Node in a BST - 이진 탐색 트리에서 노드 삭제하기

BST의 루트 `root`와 정수 `key`가 주어지면 값이 `key`인 노드를 삭제하고, 삭제 후 트리의 루트를 반환해야 한다. 삭제할 값이 없다면 기존 트리를 그대로 반환한다.

```python
# Definition for a binary tree node.
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def deleteNode(self, root: TreeNode | None, key: int) -> TreeNode | None:
        def dfs(node, key):
            if node is None:
                return None

            if key < node.val:
                node.left = dfs(node.left, key)

            if key > node.val:
                node.right = dfs(node.right, key)

            if key == node.val:
                if node.left is None:
                    return node.right

                if node.right is None:
                    return node.left

                successor = node.right

                while successor.left:
                    successor = successor.left

                node.val = successor.val
                node.right = dfs(node.right, successor.val)

            return node

        return dfs(root, key)
```

BST에서는 현재 노드보다 작은 값이 왼쪽 서브트리에 있고, 큰 값이 오른쪽 서브트리에 있다. 따라서 일반 이진 트리처럼 양쪽을 모두 확인할 필요가 없다. `key < node.val`이면 왼쪽만, `key > node.val`이면 오른쪽만 탐색한다. 탐색 중 `None`에 도착하면 삭제할 값이 없다는 뜻이므로 `None`을 그대로 반환한다.

삭제할 노드를 찾은 뒤에는 자식의 수에 따라 세 경우로 나눈다.

1. 왼쪽 자식이 없으면 현재 노드 대신 오른쪽 자식을 반환한다.
2. 오른쪽 자식이 없으면 현재 노드 대신 왼쪽 자식을 반환한다.
3. 자식이 둘 다 있으면 오른쪽 서브트리에서 가장 작은 노드를 찾아 현재 노드의 자리를 대신하게 한다.

첫 번째와 두 번째 경우에는 반환한 자식이 삭제된 노드의 위치에 바로 연결된다. 자식이 하나도 없는 리프 노드라면 왼쪽과 오른쪽이 모두 `None`이다. 이때 첫 번째 조건에서 `node.right`, 즉 `None`을 반환하므로 같은 코드로 처리할 수 있다.

자식이 둘 다 있을 때는 현재 노드를 단순히 왼쪽이나 오른쪽 자식으로 바꿀 수 없다. 그렇게 하면 반대쪽 서브트리를 잃어버릴 수 있다. 대신 오른쪽 서브트리의 최솟값인 중위 후계자(inorder successor)를 찾는다. 이 값은 현재 노드보다 크면서 현재 노드 다음으로 작은 값이므로, 현재 위치에 복사해도 BST의 대소 관계가 유지된다.

```python
successor = node.right

while successor.left:
    successor = successor.left
```

BST에서 더 작은 값은 왼쪽에 있으므로, 오른쪽 서브트리의 루트에서 왼쪽으로 끝까지 이동하면 그 서브트리의 최솟값을 찾을 수 있다. 후계자의 값을 현재 노드에 복사한 뒤에는 같은 값이 트리에 두 개 남는다. 따라서 오른쪽 서브트리에서 기존 후계자 노드를 다시 삭제한다.

```python
node.val = successor.val
node.right = dfs(node.right, successor.val)
```

여기서 재귀 호출의 결과를 `node.right`에 다시 대입하는 것이 중요하다. 후계자가 리프일 수도 있지만 오른쪽 자식을 가질 수도 있기 때문이다. 삭제로 인해 오른쪽 서브트리의 루트나 연결 관계가 달라질 수 있으므로, 재귀 함수가 돌려준 새 서브트리를 다시 연결해야 한다. 같은 이유로 왼쪽과 오른쪽에서 `key`를 찾을 때도 각각 `node.left`와 `node.right`에 재귀 호출의 반환값을 대입한다.

빈 트리, 존재하지 않는 키, 리프 노드, 자식이 하나인 노드, 자식이 둘인 노드, 루트 노드 삭제를 확인했다. 특히 루트가 `5`이고 오른쪽 서브트리의 최솟값 `6`이 다시 오른쪽 자식 `7`을 가진 경우에도, `6`이 루트로 이동하고 기존 `6`의 자리에는 `7`이 연결되어 BST 순서가 유지됐다.

트리의 높이를 `h`라고 하면 탐색에 `O(h)`, 자식이 둘인 경우 후계자를 찾고 삭제하는 데도 같은 경로 안에서 `O(h)`이 필요하므로 전체 시간 복잡도는 `O(h)`다. 균형 잡힌 BST에서는 `O(log n)`이고, 한쪽으로 치우친 BST에서는 최악의 경우 `O(n)`이다. 재귀 호출 스택도 트리 높이에 비례하므로 공간 복잡도는 `O(h)`이며, 최악의 경우 `O(n)`이다.

## 2. 스스로 묻고 답한 질문들

### Q. 자식이 하나뿐일 때 왜 그 자식을 반환하면 삭제가 될까?

재귀 함수의 반환값은 현재 서브트리의 새 루트다. 삭제할 노드에 왼쪽 자식만 있다면 `node.left`를 반환하고, 부모는 그 값을 자신의 자식 포인터에 다시 저장한다. 그러면 부모가 삭제 대상 대신 그 자식을 직접 가리키게 된다. 삭제 대상이 전체 트리의 루트여도 바깥의 `return dfs(root, key)`가 새 루트를 반환하므로 같은 원리로 처리된다.

### Q. 자식이 둘일 때 왜 오른쪽 서브트리의 최솟값을 선택할까?

오른쪽 서브트리의 모든 값은 현재 노드보다 크다. 그중 최솟값을 선택하면 왼쪽 서브트리의 값보다는 크고, 나머지 오른쪽 서브트리의 값보다는 작거나 같은 경계를 유지할 수 있다. 반대로 왼쪽 서브트리의 최댓값인 중위 선행자(inorder predecessor)를 사용해도 같은 방식으로 풀 수 있다.

### Q. 값을 복사한 뒤 기존 후계자를 꼭 다시 삭제해야 할까?

삭제해야 한다. 현재 노드의 값을 후계자 값으로 바꾸는 것만으로는 후계자 노드가 원래 위치에 그대로 남아 같은 값이 두 번 존재한다. 오른쪽 서브트리를 대상으로 `successor.val`을 다시 삭제해야 노드 수가 실제로 하나 줄어든다.

### Q. 후계자에게 오른쪽 자식이 있어도 괜찮을까?

괜찮다. 후계자는 오른쪽 서브트리에서 가장 왼쪽에 있는 노드이므로 왼쪽 자식은 없다. 후계자를 삭제할 때 `node.left is None` 조건에 걸려 자신의 오른쪽 자식을 반환하고, 부모가 그 반환값을 다시 연결한다. 따라서 후계자의 오른쪽 서브트리도 잃어버리지 않는다.

### Q. 삭제할 `key`가 트리에 없으면 어떻게 될까?

BST의 대소 관계를 따라가다가 결국 `None`에 도착한다. 그때 `None`을 반환하고, 각 부모는 반환받은 기존 서브트리를 다시 연결한 뒤 자신을 반환한다. 결과적으로 트리 구조는 바뀌지 않는다.

## 정리하며

처음에는 BST의 대소 관계를 이용해 DFS로 노드를 찾는 데 집중했지만, 실제 핵심은 삭제 이후 서브트리의 루트를 무엇으로 반환할지 결정하는 데 있었다. 자식이 없거나 하나인 경우에는 남은 자식을 올리고, 자식이 둘이면 중위 후계자의 값을 복사한 뒤 원래 후계자를 삭제하면 세 경우를 일관된 재귀 구조로 처리할 수 있었다.

또한 재귀 호출을 단순히 실행하는 데서 끝내지 않고 `node.left = ...`, `node.right = ...`처럼 반환값을 다시 연결해야 한다는 점을 확인했다. 트리 문제에서 재귀 함수의 반환값은 계산 결과뿐 아니라 변경된 서브트리의 새 루트가 될 수 있다는 점을 기억해두려고 한다.
